# Windows 本地安装

解压便携包到固定目录，例如 `D:/Tools/LaserMaker Agent`。保留 runtime 下 EXE 与 _internal 的相对位置，不需要系统 Python。仅支持 Windows x64、本地交互桌面、LaserMaker 2.1.7.2，当前驱动固定查找 `C:/Program Files/LaserMaker2/Bin/LaserMaker.exe`；执行前保存自己正在编辑的图纸。不要在远程锁屏或系统安全桌面运行 GUI 工具。

在 PowerShell 中执行：

```powershell
& 'D:/Tools/LaserMaker Agent/runtime/lasermaker-agent.exe' doctor
& 'D:/Tools/LaserMaker Agent/runtime/lasermaker-agent.exe' tools
```

doctor 检查运行时和安装路径；它不代表已经通过真实 GUI、加工或各宿主端到端验收。实际测试记录见同目录验证报告。

## Codex

根目录 plugin.json 使用官方便携插件格式。mcp.json 的 command 必须为包内相对路径 `./runtime/lasermaker-agent.exe`，cwd 使用 `${PLUGIN_ROOT}`；宿主解析为安装目录。共享 Skill 为 lasermaker-workflow。仅声明实际测试的宿主版本，不提供旧版格式兼容承诺。

从便携 ZIP 解压出的干净目录安装；源码工作目录含构建和测试缓存，不作为市场来源。已测 Codex CLI 0.164.0：

```powershell
codex plugin marketplace add 'D:/Tools/LaserMaker Agent'
codex plugin add lasermaker-agent@lasermaker-local
codex plugin list --json
```

Codex Desktop 可在插件目录中选择该本地市场。实际加载与工具调用状态见验证报告。

## Claude Code

在插件根目录运行 `claude plugin validate .` 校验；从产品工作目录启动 `claude --plugin-dir 'D:/Tools/LaserMaker Agent'`。`.claude-plugin/plugin.json` 显式引用 adapters/claude.mcp.json，以 `${CLAUDE_PLUGIN_ROOT}` 启动本地运行时。进入 `/mcp` 查看连接和工具。Codex 使用独立的便携 mcp.json。

## Kimi Code

已测 Kimi Code 2.3.2。启动 Kimi 后输入 `/plugins install D:/Tools/LaserMaker Agent`，路径请换成实际解压目录；包含空格的路径如解析有歧义，可在 `/plugins` 面板中输入完整目录。安装后 `/reload` 或新建会话，再用 `/plugins info lasermaker-agent` 检查诊断，`/plugins mcp enable lasermaker-agent lasermaker` 启用本地 MCP。使用 kimi.plugin.json、相对启动命令和共享 Skills。Kimi 将目录复制到用户管理区；修改原解压目录后需重新安装。[官方插件说明](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/plugins.html)

## DeepSeek Harness

已测 DeepSeek Harness 0.2.1-rc.2、0.2.1-rc.3、Cordis 4.0.5。0.1.4 将 `engines.dsh` 放宽为 `>=0.2.1-rc.2 <0.3.0`；本插件是原生 Cordis bundle：package.json 指定 dsh.bundle.patch，YAML 挂载 dsh-plugin-lasermaker，适配器加载官方 @deepseek-ai/dsh-mcp-client，并从适配器位置解析运行时绝对路径。在已有 Harness 环境执行：

```powershell
dsh plugin --profile laser add 'D:/Tools/LaserMaker Agent'
dsh --profile laser --dump-config
```

第一条将安装请求交给 profile 的 pnpm，第二条应显示 dsh-plugin-lasermaker。profile 中需要 @deepseek-ai/dsh-tools、dsh-skill、dsh-system-prompt 等宿主服务，并按 package.json 解决 peerDependencies；本包提供的是插件及 Python 运行时，宿主 Node.js／Harness 和模型账户由宿主环境提供。原生 bundle 加载、工具发现及实际调用证据见验证报告。

## 通用 MCP 与 CLI

任意支持 stdio MCP 的 Agent 均可使用下列配置，将路径换成真实绝对路径：

```json
{"mcpServers":{"lasermaker":{"command":"D:/Tools/LaserMaker Agent/runtime/lasermaker-agent.exe","args":["mcp"],"cwd":"D:/Tools/LaserMaker Agent"}}}
```

CLI 示例：`lasermaker-agent.exe open_project --args-file request.json`，其中内容为 `{"root":"D:/projects/cockpit"}`。MCP 工具返回结构化 JSON，并保留中文路径。若宿主不支持原生插件，可先接入通用 MCP，再加载共享 Skill；这不算原生插件加载验收。

## 开发与重建

源码包需要 Python 3.12 x64。创建虚拟环境后 `python -m pip install -e ".[dev]"`，运行 `python -m pytest -q`。依赖锁定清单为 requirements.lock.txt；`scripts/build.ps1` 构建便携运行时并打包。可选真实测试需设置 LASERMAKER_LIVE_TESTS=1；它会创建新图纸、改参数、保存和重开测试副本，不启动机器。

宿主适配压缩包是便携核心的覆盖层：将其解压到同一插件根目录。四种宿主共用一个 EXE、项目源、检查点和操作日志；切换宿主时先 resume_project，并处理未确认的 GUI 结果。

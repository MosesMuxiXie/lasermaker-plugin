# 接口、续作与边界

同一个核心通过 CLI 和 stdio MCP 提供 17 个工具。实际工具签名以 `runtime/lasermaker-agent.exe tools` 或 MCP `tools/list` 为准；CLI 对每个工具接收 `--args-file request.json`，也可用 `--json` 传 JSON。路径使用绝对路径，JSON 保存为 UTF-8。

## 项目与编辑

`create_project` 接收空目录 root、name 和 design。源文件单位固定 mm，包含 sheet_mm、material、objects；每个对象有稳定 id、role、closed，以及 points 或 SVG 路径 d。role 为 score、engrave、cut_inner、cut_outer。points 中闭合轮廓不必重复首点；d 的闭合子路径必须实际闭合。

`open_project`／`resume_project` 返回最新版本、外部原生文件变化和待核对操作。`apply_design_ops` 接收 root、request_id、expected_revision、operations。批次全部成功才落盘，修订号加一。

可用编辑：add、text、node、move、rotate、scale、mirror、duplicate、array、align、distribute、boolean、offset、delete、set_material。直线、多边形使用 points，曲线使用 d。text 需要 font_path、height_mm、position、text 和 id；height_mm 为整段可见字形轮廓的实际高度，position 为其左上角，保存的是字形路径，缺字会拒绝。字体文件需由本机提供，插件不分发系统字体。布尔只接受单个有效多边形结果，复杂分裂结果会明确报错。复合闭合路径按奇偶嵌套保留内孔。offset 是轮廓偏移，不能自动判断材料内外的切缝方向。更换板厚后必须另行调整榫槽结构。

例如移动并复制一个对象：

```json
{"root":"D:/projects/cockpit","request_id":"edit-001","expected_revision":0,"operations":[{"op":"duplicate","ids":["part-outline"],"dx":140,"dy":0,"suffix":"-2"}]}
```

复制整零件时同时选择外轮廓及该零件孔槽、标记；仅复制标记会保持其所属零件关系。array 使用 columns、rows、dx、dy；rotate 使用 degrees、origin；scale 使用 sx、sy、origin；node 使用 id、index、point。align 使用 ids、axis、mode、value；distribute 按所选对象现有范围均布。boolean 使用 mode=union/difference/intersection、result_id；offset 使用 distance，正值向外。

## GUI 工作流

依次调用 `import_design` → `set_layer_process` → `save_native` → `reload_and_verify` → `checkpoint` → `export_delivery`。前四项均需 root、request_id、expected_revision。导入会建立新图纸，成功后绑定当前项目和文档名；当前文档改变或源版本改变后，工艺与保存调用会拒绝继续。

工艺示例仅说明字段，并非生产参数：

```json
{"root":"D:/projects/cockpit","request_id":"process-001","expected_revision":0,"color":"#ff0000","process":{"mode":"score","speed_mm_s":100,"power_max_percent":15,"power_min_percent":13}}
```

mode 支持 cut、score、engrave、shallow_engrave。速度为 mm/s，功率为百分比。power_min_percent 指切割／描线的转角功率；浅雕／深雕没有此项，传入会拒绝。每次修改读取实际存在的参数和图层表确认；现场人员仍需按设备及材料试切。

源码角色 engrave 统一输出为蓝色。需要同一产品同时浅雕和深雕时，将两种雕刻分成独立工程／阶段，各自设置 shallow_engrave 与 engrave，保持材料定位；不要将需要不同参数的内容合并成同一蓝色图层。普通 LaserMaker 手工工程可另分颜色，工艺以参数框实际读回为准。

`save_native` 的 filename 必须为项目内不存在的 .lcpx 路径，实际文件名自动加项目 ID 前缀，避免同名文档跨项目混淆；使用返回 path 继续操作。`reload_and_verify` 只允许重开已关联当前源版本和摘要的文件，expected_size_mm 可指定期望选区宽高。重开后用 `verify_layer_process` 核对实际工艺、速度、最大及转角功率；结果写入交付证据。最后可用 `close_verified_document` 关闭已保存且重开核验的绑定图纸，避免长期编辑达到软件文件数上限；已知存在未保存参数时会拒绝关闭。

`read_design` 仅解析 PRJF11.12 文件头，不将其当作完整几何或工艺证据。`capture_app` 只截 LaserMaker 窗口，OCR 属于辅助证据。正常屏内窗口移动使用新控件位置继续操作；本机曾在窗口完全移出屏幕后持续产生空截图，这一情况暂不能自动恢复，需保留图纸后恢复应用。不要把该情况计为移位恢复通过。

每次 GUI 调用有独立进程和 90 秒上限；内部驱动截止时间 80 秒。全局桌面锁和项目服务锁避免多 Agent 同时操作。必须使用解锁的本地交互桌面；未知弹窗、版本不匹配、无法取得焦点时停止该步并保留现状。驱动不发送机器任务。

Qt 参数编辑需要真实前台点击与键盘输入。连续桌面测试或长任务期间应保留 LaserMaker 前台；其他应用抢占焦点时，驱动会停止，不会把参数输入到遮挡应用。几何生成、预检和导出可在后台进行。OneDrive／杀毒软件的短暂文件共享冲突只会重试同一份原子状态快照，最多约 2 秒，不会重放 GUI 动作；持续占用仍会返回失败并保留未确认状态。

## 重试与接续

超时后先 `resume_project`、`inspect_app`，检查 operations 目录与磁盘产物。几何编辑使用原 request_id、原 expected_revision、原 operations 完整重放；即使当前版本已经增加，也不能修改重放载荷。原子回执保证返回原结果；相同 ID 配不同载荷会报 REQUEST_CONFLICT。

GUI 操作开始前记录 started，结果确认后记录 complete。若状态为 needs_reconciliation，禁止以新 ID 盲目重做导入或复制。检查实际文档、文件路径和读回结果，保留证据后由操作者核对；当前版本没有自动接受未知 GUI 结果的接口。可继续只读检查和导出已有确认的几何，不能宣称未确认的原生交付已完成。

发现原生文件哈希改变时，保留原生文件和源文件副本，另建项目处理差异。插件不会用原有源数据重新导入覆盖用户修改；原生格式解析尚不能将任意 GUI 手工编辑自动合并回源文件。检查点保存快照，resume 始终返回最新版本，不自动退回旧检查点。

## 交付与已知限制

预检检查闭合、轮廓有效性、重复切割、板材范围、孔槽归属、零件相交、连接余量和标记是否位于保留材料。曲线检查与 DXF 采用自适应折线近似；SVG 保留原曲线。几何容差 0.01 mm，GUI 读回容差 0.05 mm，均不表示机器加工精度。

只有完整源图形对应的当前修订版本原生工程已保存、重新打开、哈希未变化，且没有已知未保存参数变更时，export_delivery 才附带原生文件。分阶段导入的工程不会冒充完整工程。原生工艺写入前即记录 dirty，失败或中断保持该标记。导出目录包含实际原生内容标识，保留历史交付。

原生关联还必须匹配当前 export_profile。旧导出器生成的工程、或没有记录导出版本的工程，不能直接重开或另存后升级为当前交付；返回 NATIVE_EXPORT_PROFILE_MISMATCH_REIMPORT_REQUIRED，须先保留旧文件，再用当前源重新导入新图纸。SVG 闭合轮廓保留最后一段圆弧／贝塞尔曲线，随后显式闭合；样例执行逐对象毫米轮廓回读检查。

导出包含源 JSON、SVG、DXF、分阶段 SVG、检查报告、SHA-256 清单。实际走刀顺序和仿真未确认时，使用描线／雕刻、内切、外切分阶段图纸；不可将源文件顺序当作设备执行顺序。

本版 manufacturing_ready 始终为 false；几何和软件证据通过后，仍待机器、材料、参数及实机试切确认。
